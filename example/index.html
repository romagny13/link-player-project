LinkPlayer : page d'exemples

YouTube et OK.ru, en trois modes (link only, code only, mixed), plus les options (showOnInit, useStorage, currentBehavior, defaultTarget), l'API YouTube Data, les dépendances de vue, l'adoption d'iframes et un LinkPlayer global à côté d'un LinkPlayer « scopé ». Chaque section a son propre scope et ses propres cibles ; le journal à droite reçoit tous les événements change / state / error.

À servir en HTTP(S) (par exemple npx vite), pas en file:// : les modules ES et crypto.randomUUID() l'exigent. Adapte l'import de LinkPlayer en bas de la page si besoin.

1 · Link only : tout est défini sur les data-link

Aucune définition en code. Titre, chaîne, miniature, autoplay, start et data-videos sont lus sur le lien. Tous les liens visent la même cible player-link : passer d'un lien OK.ru à un lien YouTube remplace l'iframe et le panneau.

Dans les exemples d'origine, les métadonnées s'appelaient data-items et "id" ; les parsers lisent data-videos et "videoId" (pour les playlists). 2 · Code only : définitions + boutons liés aux méthodes de la région

Pas un seul lien dans le HTML. Les infos viennent du tableau definitions ; les boutons ci-dessous sont générés depuis region.infos et appellent region.navigate(key, {autoplay}). Le LinkPlayer est créé avec autoScan: false puis on appelle scan() à la main. La première définition a showOnInit: true.

Le bloc « détails » utilise region.registerDependentView() : la fonction est appelée à chaque changement d'item dans une liste ou playlist ; pour un changement d'info on écoute region.on("change").

3 · Mixed : les liens naviguent, les définitions décrivent

Les liens n'ont que data-link (ni data-target, ni titre) : la cible vient de defaultTarget. Les infos sont celles de definitions : un lien retrouve sa définition parce que sa key est la même (par défaut youtube:ID, youtube:list:ids, youtube:playlist:PL…, okru:ID, ou data-key). Survole les liens : l'infobulle montre la définition.

4 · Comportements : currentBehavior, useStorage, showOnInit, defaultTarget

Mêmes liens, deux LinkPlayer. Clique deux fois sur le lien en cours : avec "toggle" le lecteur se masque puis se ré-affiche, avec "skip" il ne se passe rien. Le premier lien de chaque zone a data-show-on-init (affiché au chargement). À gauche useStorage: true : recharge la page, le dernier lien est restauré (et prime sur showOnInit) ; à droite useStorage: false : on repart toujours de showOnInit.

6 · Adoption d'iframes existantes (playlist et liste de vidéos)

Ces iframes sont déjà dans la page ; le LinkPlayer les reconnaît, lit leur src (list= pour la playlist, playlist=a,b&index=2&start=120 pour la liste), les pilote et ajoute le panneau. Chaque iframe est dans son propre conteneur (un conteneur = une région = un seul item actif).

Playlist embed/videoseries?list=…

Liste de vidéos embed/?playlist=…&index=2&start=120

À l'adoption, YouTubePlayer recharge l'iframe une fois pour y ajouter enablejsapi=1 et origin (sinon aucune commande ne passerait).

7 · Un LinkPlayer global, un LinkPlayer scopé sans infobulle

Le LinkPlayer global (sans scope) regarde tout le document, avec infobulles, "toggle" et defaultTarget: "player-global". Le LinkPlayer scopé ne voit que #zone-scoped, sans infobulle, avec "skip". Un lien déjà pris en charge (data-lp) est ignoré par l'autre : les scopés sont donc créés avant le global (voir le script), sinon le global prendrait leurs liens.
