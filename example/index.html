LinkPlayer: examples page

A living mini documentation. Each section has its own scope and its own targets; the info shown under each player is rendered by region.afterNavigate(); the log (at the bottom) receives the change / state / sound / error events.

Serve it over HTTP(S) (e.g. npx vite), not file://. Adapt the import at the bottom of the page.

1 · Link only: everything is defined on the data-link elements

No definitions in code. A single target area (player-link) for all the links; a shared info area below it, fed by afterNavigate. Each link has a distinct data-key (the default key is the video / list / playlist id: two links to the same video would share the same info).

2 · With definitions: links navigate, definitions describe

The link only carries data-link, data-key and data-target; the info comes from the definitions array (same key). Definitions are registered before the scan: they win over the info on the link. Hover the links: the tooltip shows the definition.

4 · YouTube Data API: default info, then loaded info

Shows two states of the same info: (1) the default info (data on the link or in a definition, then fallbackTitle); (2) the info loaded through the API (change event with reason = "meta"). Resolver priority: declared values > API > fallback. A value that is already declared is not overwritten: the API fills in the empty fields. Without a key (see the top of the page), only the fallback applies.

6 · Code only: definitions + navigation methods

No links in the HTML. autoScan: false, then scan() by hand; the first definition has showOnInit: true. The buttons are generated from region.infos and call region.navigate(key, {autoplay}).

7 · A global LinkPlayer and a scoped LinkPlayer (no conflict)

The global one (no scope): tooltip enabled, "toggle". The scoped one (#zone-scoped): tooltip: false, "skip". An element that is already handled (data-lp) is ignored by the other one: scoped instances are created before the global one.

8 · Navigation buttons and behaviors

Each button bar is wired to its region: back / forward, previous / next info, previous / next item (list or playlist), show / hide. Buttons are greyed out according to canGoBack, canGoForward, canGoPreviousInfo, canGoNextInfo, canGoPreviousItem, canGoNextItem.

  • currentBehavior (click on the link already shown): "toggle" hides / shows again, "skip" does nothing, "playPause" switches between play and pause.
  • boundaryBehavior (at the ends of nextInfo() / previousInfo()): "stop" stops, "loop" wraps around (at least 2 infos are needed).
  • useStorage and showOnInit: the "toggle" zone has useStorage: true (reload the page: the last link is restored and wins over showOnInit).

9 · Format (short) and muted start

FormatBehavior sets data-lp-format on the container: click from one link to another and the area changes shape. The format comes from the URL (/shorts/ID → portrait) or from data-format (portrait, 9/16, square, landscape).

a. Format and mute on click

  • Short detected from the URL: Short (portrait detected)
  • Short, autoplay + muted (data-autoplay="click" data-mute): Short, muted autoplay
  • Forced format on an ordinary video: Maldives in 9/16 (forced) | Maldives in square
  • YouTube, autoplay + muted: Maldives, muted autoplay
  • OK.ru, autoplay + muted (only if the relay applies mute): OK.ru, muted autoplay
  • Control, autoplay with sound: Tahiti, autoplay with sound

b. On page load, without a user gesture
