LinkPlayer — examples

Each zone has its own data-target and remembers what is played in it. Reload the page: each zone resumes at the last link and the last episode (paused, as browsers block autoplay upon loading). Keys (data-key) are explicit everywhere, because two YouTube /watch URLs would generate the same key.

YouTube

Playlists using list= require a YouTube Data API key (window.__YTP_API_KEY__) to display the panel. Dynamic playlists (video_ids) work without a key, using generic titles. The panel open button is at the bottom left of the player, visible on hover.

The panel is open by default. Its toggle (if you close it) is at the top right. Seasons are detected in titles (S2, Season 2) or specified via data-seasons.

Single zone, multiple services

The same target alternately receives YouTube, Ok.ru, and Dailymotion. On each change, the player is replaced, the panel follows the service (or disappears), and the save state is updated.

  • YouTube dynamic playlist: panel closed, bottom-left button.
  • Ok.ru playlist: panel open, top-right reopen button.
  • Standalone video or Dailymotion: no panel, no button.
  • Quick clicks on multiple links in a row: only the last one should display.
  • Previous / Next: returns to the previous link of this zone, at the episode where you were.

Autoplay

data-autoplay determines when playback starts automatically: none (default) never, click only after a click, always (or empty attribute) also on initial display. Even when set to always, restoration after a reload remains paused. Browsers may also refuse autoplay with sound without prior user interaction.
